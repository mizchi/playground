VERDICT: worse

The new `weightBasedRate` helper is a generic-sounding wrapper around four positional numeric parameters with no semantic labels, which is a classic complexity/duplication-metric gaming pattern: it reduces line count and "duplicated" literal branches, but at the call site `weightBasedRate(weight, 300, 600, 1200, 3000)` you can no longer tell which number is which rate tier without cross-referencing the function signature — the original code's `if (weight < 1) return 300;` was self-documenting, this isn't. The two call sites also aren't actually duplicate logic that deserved extraction — they're two different rate tables sharing a threshold *shape*, not shared business logic — so the abstraction doesn't correspond to a meaningful domain concept. A reader now has to jump between two locations and mentally re-zip the parameter list with the thresholds to understand what shipping costs what, which is strictly worse than the flat, linear if-chain it replaced.
