VERDICT: worse

The extraction turns a self-explanatory, country-specific tier table into a generic-named helper (`weightBasedRate`) called with four bare numeric positional arguments. At the call site (`weightBasedRate(weight, 300, 600, 1200, 3000)`), there's no way to tell which number is which tier without cross-referencing the function signature — the original inline version showed the threshold and its rate on the same line, which was easier to scan and verify. This is a classic case of gaming a duplication/complexity metric: it removes the "duplicate" if/return structure (which a checker like jscpd or a cyclomatic-complexity linter would flag), but the duplication being removed was cheap, readable, tabular data, not real logic duplication. The new version doesn't reduce actual complexity — it just hides the branching in a parameterized function and pushes the reader to jump between two locations to understand what any given call produces. It also invites bugs if someone ever passes the four rates in the wrong order, with no named parameters or types to catch it.
