# 使い分けの整理：いつ・どこで・どの入力量で・どの出力に、何を使うか

この実験（`ts/`・`rust/`・`bench/`・`explainer/`）の計測と、調べた資料を、4 つの軸で整理したもの。
根拠の列の「計測」はこのディレクトリで測った値、「資料」は他のリポジトリや論文の値、「未計測」は予想。

## 4 つの軸

| 軸 | 区分 |
|---|---|
| いつ（推論） | リクエストごとに同期で呼ぶ（予算 µs）／非同期・バッチでよい（予算 ms）／オフラインで集計 |
| いつ（学習） | オフラインで一括／定期的に再学習（日次など）／リクエストごとに逐次更新（オンライン） |
| どこで | ブラウザ／Node サーバ／Rust サーバ／カーネル・`no_std`・マイコン／手元の学習環境 |
| 入力量 | 特徴量の次元（〜数十の表形式／〜数百のハッシュ特徴／数万以上の画像・文章）、学習の行数、推論のバッチの大きさ |
| 出力 | 二値（入れる・入れない）／順位／回帰（時間・遅延）／多クラス／埋め込み・生成 |

決める順番は、出力の保証 → いつ・どこで → 入力量 → 出力の形。

1. 出力に正しさの保証が要るなら、ML の出力はヒントにとどめ、最終判断は古典的な仕組みにする（learned Bloom filter の backup、キャッシュミス）。
2. いつ・どこで呼ぶか（遅延の予算と、同期か非同期か）で、推論の実行方法が決まる。
3. 入力量で、モデルの種類（LR・MLP・GBDT・それ以上）が決まる。
4. 出力の形で、最後の層と損失が決まる。

## 推論：いつ・どこで・どの入力量なら、何を使うか

| いつ | どこで | 入力量 | 使うもの | 根拠 |
|---|---|---|---|---|
| 同期、予算 µs | TS（ブラウザ・Node） | 数百次元以下、1 行ずつ | 自前の LR・小さい MLP（`Float32Array`） | 計測：問い合わせ全体で約 4µs（特徴量づくりが大半） |
| 同期、予算 µs | Rust サーバ | 数百次元以下、1 行ずつ | 自前 + 重みを `const` に（int8 にもできる） | 計測：1 行 91〜282ns（256 次元の MLP は 1.0µs） |
| 同期、予算 ns〜µs | カーネル・`no_std`・マイコン | 数十次元以下 | 自前の int8、整数のパーセプトロン。`.tflite` があるなら `microflow` | 計測：パーセプトロン分岐予測。資料：MicroFlow の論文 |
| 非同期でよい、予算 ms | ブラウザ | 数百〜数万次元、バッチ 16 以上 | WebNN（`mizchi/webnn-mbt`）か onnxruntime-web | 資料：webnn-mbt の BENCHMARK.md。1 回の呼び出しに 35〜50µs、MNIST のバッチ 100 で素朴な CPU 実装の 1/85 |
| 同期か非同期 | Node サーバ | 表形式で GBDT が要る | LightGBM で学習 → ONNX → `onnxruntime-node` | 未計測 |
| 同期か非同期 | Rust サーバ | 表形式で GBDT が要る | LightGBM で学習 → Rust で推論（`lightgbm3`、ONNX + `tract`、木を自前で評価） | 計測：学習は LightGBM が 0.4〜2.0 秒、`perpetual` が 1.4〜304 秒。推論の経路は未計測 |
| どこでも | Python から呼ぶ | — | 避ける | 計測：scikit-learn・LightGBM の 1 行推論は 23〜90µs（まとめて推論すれば速い） |

## 学習：いつ・どの入力量なら、何を使うか

| いつ | 入力量 | 使うもの | 根拠 |
|---|---|---|---|
| オフライン・定期的 | 10 万行程度 × 数百次元、LR・MLP | 自前（Rust か TS） | 計測：6 万行 × 256 次元を Rust 0.26〜0.79 秒、TS 1〜3 秒。scikit-learn は 0.60〜1.34 秒 |
| オフライン・定期的 | 表形式で、LR・MLP の精度が足りない | Python の LightGBM（ここが Python の出番） | 計測：AUC は url で 0.984 → 0.994。cache ではほぼ変わらない |
| オフライン・定期的 | 表形式で数十次元以下、Rust だけで済ませたい | `perpetual`（nightly が必要） | 計測：18 万行 × 11 次元で 1.4〜2.5 秒。256 次元では 304 秒 |
| リクエストごと（オンライン） | 1 件ずつ、数百次元以下 | 自前の SGD かパーセプトロン（1 件ごとに重みを更新） | 計測：パーセプトロン分岐予測 |
| 特徴量を探す段階 | — | Python（scikit-learn・LightGBM の重要度） | — |

## 出力：期待する出力なら、最後の層と損失は何にするか

| 期待する出力 | 最後の層と損失 | この実験のコード |
|---|---|---|
| 二値（入れる・入れない、ある・ない） | sigmoid + 交差エントロピー、閾値 τ | `nn.ts`・`lib.rs` のまま |
| 順位（どれを追い出すか） | スコアを比べるだけ。学習は二値か回帰で行う | 二値のまま使える |
| 回帰（次のアクセスまでの時間、遅延） | 線形の出力 + 二乗誤差。時間は log を取ってから学習 | 未実装。出力の誤差は同じ `ŷ - y` の形なので、出力層の sigmoid を外すだけ |
| 多クラス | softmax + 交差エントロピー | 未実装。出力の誤差は同じ `p - y` の形 |
| 埋め込み・文章・画像 | この整理の範囲外 | ONNX・WebNN・LLM の領域 |

## 手段ごとの評価：気軽さ・JS で使える度・Rust で使える度・それ以外で使える度

◎ そのまま使える（計測あり）、○ 少し手を入れれば使える（重み・モデルの書き出し経由を含む）、△ 条件が厳しいか未計測、× 現実的でない。
「使える度」は、その言語の製品の中で推論を動かせるか。学習専用の道具は、作った重み・モデルの持ち込みやすさで見る。
数字はすべて `bench/README.md` の計測（キャッシュ容量 0.5%、OHR はリクエスト数、BHR はバイト数で数えたヒット率）。

| 手段 | 気軽さ | JS | Rust | それ以外 | 根拠 |
|---|---|---|---|---|---|
| TS 自前（LR・MLP、`nn.ts`） | ◎ | ◎ | ○ | ○ | 依存 0、201 行。1 行推論 86〜366ns（同期）。BHR 17.39%。Rust などへは推論 30 行を移して重みを渡す |
| Rust 自前（LR・MLP、`lib.rs`） | ◎ | ○ | ◎ | ◎ | 依存 0、ビルド 0.7 秒。1 行推論 30〜110ns、BHR 17.52%。`no_std`・wasm・C ABI に出せる。JS へは wasm か推論を移植 |
| `moka`（TinyLFU） | ◎ | × | ◎ | ○ | `cargo add` で差し替えるだけ、学習なし。OHR 約 36%。Rust 専用だが、同じ系統のアルゴリズムは Java（Caffeine）・Go（Ristretto）にある |
| `quick_cache`（S3-FIFO） | ◎ | × | ○ | △ | 差し替えるだけ。OHR 22.5%、BHR 15.1% で中間。S3-FIFO は単純なので自前で移しやすい |
| scikit-learn | ◎ | ○ | ○ | ○ | 1 行で学習。Python での 1 行推論は 63〜90µs で製品には不向き。LR・MLP の重みを書き出せば各言語で自前推論できる |
| LightGBM | ◎ | △ | △ | ◎ | 2 行で学習、0.37〜2.0 秒で最速。JS・Rust へは ONNX か C API 経由（未計測）。C API と R・Java などのバインディングがある |
| JAX（微分可能プログラミング） | ○ | ○ | ○ | ○ | `pip install jax`、損失 15 行、14.6 秒。OHR を直接最適化して 40.0%（最高）。学習専用で、小さい MLP の重みを各言語へ持ち出す |
| Rust `std::autodiff` | △ | △ | ○ | △ | nightly + enzyme + `lto = "fat"` が必要で実験的。普通の for ループを微分でき、JAX と同じ結果（OHR 39.99%）。学習は JAX の 7 倍遅い |
| `perpetual`（純 Rust GBDT） | △ | △ | ○ | ○ | 36 crate、nightly が必要、ビルド 18.8 秒。256 次元で学習 304 秒。BHR 16.9% で MLP と同じ。Python・R のバインディングがある |
| ONNX ランタイム（`onnxruntime-node`・`ort`・`tract`） | ○ | △ | △ | ◎ | 他所で学習したモデルの標準の持ち出し先。この実験では未計測（1 回の呼び出しの手間を測っていない） |
| WebNN（`mizchi/webnn-mbt`） | × | △ | × | △ | Chrome Canary とフラグが必要で、非同期。1 回の呼び出しに 35〜50µs。バッチ 16 以上や大きめのモデルで速い（webnn-mbt の BENCHMARK.md） |

組み合わせると、次のようになる。

| 製品 | 推論（製品の中） | 学習・目的の設計（製品の外） |
|---|---|---|
| JS | TS 自前の LR・MLP（重みを JSON で受け取る） | JAX か Rust 自前。TS 自前で学習しても数秒で済む |
| Rust | `moka`（OHR が目的なら、ML なしで十分）か、Rust 自前の LR・MLP・TTL モデル | JAX で目的を試し、決まったら Rust 自前か `std::autodiff` に移す |
| それ以外（マイコン・他言語） | 重みと推論 30 行を移植（int8 にもできる） | どれで学習してもよい。成果物は数百個の数値 |
